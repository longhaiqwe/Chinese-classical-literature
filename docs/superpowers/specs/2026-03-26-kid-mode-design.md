# 幼儿阅读模式设计

日期：2026-03-26

## 背景

当前应用的插图风格、文案语气、按钮表达和答题反馈，整体更偏向学龄男孩和稍年长读者。用户现在的核心使用场景是陪一位 4 岁半女孩反复阅读《西游记》故事，其中《三打白骨精》和《真假美猴王》是高频内容。

现有体验的主要问题：

- 插图风格偏写实、偏少年感，不够 Q 版和亲和。
- 正文叙述偏文雅、抽象、句子长，不适合 4 岁半儿童理解。
- 交互反馈带有明显“闯关”和“答错”意味，不够陪伴式。
- 当前产品默认气质更接近“古典文学闯关”而不是“幼儿陪读故事”。

## 已确认的产品决策

- 采用“双层内容模式”，而不是纯前端换皮，也不是拆成两套完全独立故事。
- 产品默认进入 `幼儿版`，普通版退居次级入口。
- 幼儿版仍保留原故事冲突张力，不刻意弱化《西游记》的戏剧性。
- 幼儿版保留选择题互动，但交互语气更温柔，降低失败感。
- 第一阶段只试点两个故事：
  - `三打白骨精`
  - `真假美猴王`
- 这两个故事都归属《西游记》，可共享一套幼儿化视觉与文案方向。

## 目标

- 让 4 岁半儿童可以在默认路径中顺畅阅读和理解试点故事。
- 保留原故事结构、场景顺序和核心抉择逻辑，避免维护两套剧情骨架。
- 支持家长随时切回普通版，且切换后内容立即刷新。
- 为后续逐篇补全其它故事的幼儿版建立可扩展的数据结构。

## 非目标

- 第一阶段不重写所有故事。
- 第一阶段不为幼儿版单独制作语音资源，但需要为后续扩展预留结构。
- 第一阶段不重做整套玩法，仅对现有玩法做语气、文案和插图层面的幼儿化改造。

## 方案选择

本设计选择“覆盖层”方案。

含义是：

- `stories`、`scenes`、`scene_options` 继续保留现有普通版数据。
- 在原有记录上追加幼儿版字段，而不是新增一套 `kid_stories` / `kid_scenes` / `kid_options` 表。
- 运行时根据当前模式，优先显示幼儿字段；若缺失则可按规则回退普通字段。

不选“两套独立表”的原因：

- 维护成本高。
- 普通版一旦改剧情，幼儿版容易不同步。
- 当前只试点两个故事，没必要过早把结构做重。

## 用户体验设计

### 模式定位

模式名建议使用“阅读模式”，值为：

- `kid`
- `default`

避免用“儿童锁”“低龄版”等词，减少功能化和限制感。

### 默认行为

- 首次打开应用时默认进入 `kid`。
- 模式选择写入本地存储。
- 后续打开应用时优先沿用上次选择的模式。
- 若本地尚无记录，则仍默认 `kid`。

### 首页

- 在首页标题区放置轻量模式胶囊，例如 `幼儿版 · 已开启`。
- 切换入口可见但不抢主视觉，避免孩子频繁误触。
- 《西游记》作为试点分类，不需要额外改导航结构。

### 故事列表

- 每个故事卡片根据当前模式显示对应简介。
- 若当前为幼儿模式且某故事幼儿内容未完成，在卡片上显示轻提示，例如 `幼儿版准备中`。
- 第一阶段中，《三打白骨精》和《真假美猴王》应显示为完整支持。

### 故事页

- 标题区保留轻量模式切换入口，方便家长临时切回普通版。
- 切换模式后当前页面内容即时刷新：
  - 标题
  - 叙述
  - 选项
  - 反馈
  - 插图
- 幼儿版继续保留互动，但整体语气从“闯关”转向“陪伴式讲故事”。

### 幼儿版语气

- 允许保留紧张和冲突，但减少抽象判断、文言式解释和过重的失败感。
- 答错反馈避免强烈“惩罚”语气，优先采用陪伴式表述，例如：
  - “我们再想想”
  - “悟空这次要更小心一点”
  - “换个办法保护师父吧”

## 内容结构设计

幼儿版与普通版共用以下内容骨架：

- category
- story
- scene 顺序
- 选项正确性 `is_correct`

幼儿版额外覆盖以下展示层内容：

- 故事标题与简介
- 每幕标题
- 每幕叙述
- 每个选项文案
- 每个选项反馈
- 幼儿版插图
- 后续可扩展为幼儿版语音

## 数据库设计

### `stories`

在现有字段基础上新增：

- `kid_title text null`
- `kid_description text null`
- `kid_ending_title text null`
- `kid_ending_description text null`
- `kid_content_status text not null default 'none'`

`kid_content_status` 建议枚举语义：

- `none`：没有幼儿版内容
- `draft`：有部分内容但未达到可上线标准
- `ready`：幼儿版完整可用

第一阶段上线时：

- `sandabaigujing` 标记为 `ready`
- `zhenjiameihouwang` 标记为 `ready`
- 其它故事大多为 `none`

### `scenes`

在现有字段基础上新增：

- `kid_title text null`
- `kid_narrative text null`

说明：

- `environment_description` 与 `character_state` 暂不新增幼儿字段。
- 第一阶段这些字段主要用于生成和管理，不直接暴露给儿童读者。

### `scene_options`

在现有字段基础上新增：

- `kid_text text null`
- `kid_feedback text null`

说明：

- 不新增 `kid_is_correct`。
- 普通版和幼儿版共用同一个选项正确逻辑，保证故事骨架一致。

### `scene_images`

不建议增加 `kid_image_url` 列。

建议新增：

- `mode text not null default 'default'`

并以 `(story_id, scene_index, mode)` 作为唯一标识语义。

这样一幕可以同时拥有：

- `default` 图片
- `kid` 图片

优点：

- 图片模式更自然，可扩展到更多风格。
- 不会把一张表不断塞进 `xxx_image_url` 字段。

### `scene_narrations`

第一阶段不强制制作幼儿语音，但建议同步为后续预留：

- `mode text not null default 'default'`

这样后续可为同一幕单独生成 `kid` 语音，而不需要再次改表。

### 类型与生成物同步

当前仓库里的类型文件与实际使用表名存在历史残留，后续实现时需要在 migration 后重新生成数据库类型，保证代码中的表结构定义与 Supabase 实际 schema 一致。

## 前端架构设计

### 全局模式状态

应用层新增全局 `readingMode` 状态：

- `kid`
- `default`

该状态来源：

1. 应用启动时从本地存储读取
2. 若无记录，默认 `kid`
3. 用户切换后实时更新状态并写回本地存储

### 数据映射层

不建议让组件层到处写 `kid_title ?? title` 判断。

建议把模式判断集中到数据映射层，由 `storyService` 或其上层包装逻辑输出“当前模式下应显示的内容”，例如：

- 故事显示标题
- 故事显示简介
- 场景显示标题
- 场景显示正文
- 选项显示文案
- 选项显示反馈
- 当前模式对应图片 URL
- 后续可扩展当前模式对应音频 URL

这样组件层只消费“已解析好的显示值”，减少条件分支扩散。

### 组件影响范围

第一阶段预计需要影响以下界面：

- `App.tsx`
- `components/HomeView.tsx`
- `components/CategoryView.tsx`
- `components/StoryCard.tsx`
- `components/GameScene.tsx`
- `services/storyService.ts`

其中重点在：

- 全局模式状态和持久化
- 列表页的幼儿版可用性提示
- 故事页的模式切换与即时重渲染
- 服务层的模式映射逻辑

## 内容回退与容错策略

### 故事级容错

若当前为幼儿模式且故事 `kid_content_status != 'ready'`：

- 在故事卡片上明确标识 `幼儿版准备中`
- 第一阶段建议不让未完成的故事悄悄以成人文案进入幼儿主路径

这样可以避免孩子点进去后突然遇到过深的文案。

### 字段级回退

实现层仍需支持字段级回退，规则如下：

- 幼儿模式下，优先读取 `kid_*`
- 若个别字段为空，可临时回退普通字段

但产品要求上，第一阶段试点的两篇故事必须做到完整覆盖，不允许出现一半幼儿文案、一半成人文案的混搭体验。

### 图片回退

- 技术上允许幼儿图缺失时回退普通图，保证页面可用。
- 产品上要求试点故事补齐完整 `kid` 图片资源，避免风格跳变。

## 试点范围

第一阶段严格限定在《西游记》中的两篇故事：

- `三打白骨精`
- `真假美猴王`

范围包含：

- 默认幼儿模式
- 首页/故事页模式切换
- 幼儿版故事简介
- 幼儿版 scene 标题和叙述
- 幼儿版选项文案
- 幼儿版反馈文案
- 幼儿版插图接入
- 列表页的幼儿版状态提示

范围不包含：

- 其它故事完整补齐
- 幼儿版独立语音生成
- 全应用视觉大翻新

## 内容原则

针对幼儿版试点内容，约束如下：

- 保留原故事的紧张感和冲突张力
- 不把妖怪和危险彻底“洗白”
- 句子更短
- 叙述更具体
- 降低抽象概念密度
- 降低文言、成语、典故式解释比重
- 选项更像“帮角色做决定”，而不是成人读者答题
- 反馈更像陪伴式提醒，而不是裁决

## 验收标准

- 首次打开应用时默认进入幼儿模式。
- `三打白骨精` 和 `真假美猴王` 可在幼儿模式下完整阅读。
- 两篇故事从首页到结尾的文案明显比普通版更适合 4 岁半儿童理解。
- 幼儿模式下两篇故事的插图具有统一、柔和、Q 版的视觉表达。
- 互动仍然存在，但明显弱化“闯关失败感”。
- 家长可随时切换回普通版，切换后当前内容立即更新。
- 其它未支持幼儿版的故事在幼儿模式下有明确状态提示，而非无提示回退。

## 风险与注意事项

- 若只完成前端切换、不补充幼儿内容，会造成“幼儿模式名不副实”。
- 若试点故事只完成部分场景，会出现体验断层，影响用户判断。
- 若模式判断散落在各组件内，后续扩展成本会快速上升。
- 若不在第一阶段定义清楚 `ready` 状态，后续列表页提示会混乱。

## 推荐实施顺序

1. 增加数据库字段与模式列，并更新类型。
2. 扩展服务层读取逻辑，支持模式化映射。
3. 接入全局 `readingMode` 状态和本地持久化。
4. 完成首页、列表页、故事页的模式切换 UI。
5. 补齐 `三打白骨精` 和 `真假美猴王` 的幼儿文案。
6. 补齐这两篇故事的幼儿插图资源。
7. 联调回退逻辑与状态提示。
8. 用真实阅读路径验证默认幼儿版体验。

## 结论

本设计通过“同一剧情骨架 + 幼儿展示覆盖层”的方式，为应用增加默认开启的幼儿阅读模式。第一阶段聚焦《西游记》的两篇高频故事，以最小但完整的产品闭环验证低龄儿童是否更容易理解、是否更愿意反复阅读，以及家长是否能无缝在幼儿版和普通版之间切换。
